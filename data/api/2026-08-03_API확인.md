## 1. 호출 정보 — PRD와 다른 점이 셋

| 항목 | PRD가 적은 것 | 실제 |
|---|---|---|
| 발급처 | 공공데이터포털 (§12 「인증키는 세 종류다」) | **국립수산과학원 홈페이지** (`nifs.go.kr`) |
| 주소 | 명시 없음 | **`https://www.nifs.go.kr/api/OpenAPI_json`** |
| 창구 | 「RISA와 같은 기관이지만 별개 창구」(§1) | **같은 시스템.** id가 문자 그대로 `risaList` |

**활용가이드 PDF의 주소는 틀렸다.** 문서는 `https://www.nifs.go.kr/OpenAPI_json`이라 적었으나
실제로는 **302 리다이렉트**가 걸리고 실주소는 `/api/OpenAPI_json`이다.
`curl`에 `-L`을 붙이지 않으면 **0바이트**가 돌아온다. 처음 호출이 실패한 원인이었다.

**인증키는 서비스마다 다르다.** 4종을 신청했고 넷 다 승인(2026-08-03), 활용기간 ~2027-08-03.
우리가 쓰는 것은 **실시간어장정보** 키 하나. `.env`의 `NIFS_KEY`.

### 두 기능

| id | 무엇 | 변수 | 주기 |
|---|---|---|---|
| `risaCode` | 관측소 목록 | `key` · `gru_nam`(동해E/서해W/남해S/동중국해EC) · `use_yn` | 수시 |
| `risaList` | **최신 관측값 (전국 스냅숏)** | **`key` 하나뿐** | 30분 |

## 2. 서산 창리(fsch6) — 있다

| 항목 | 값 | PRD 대조 |
|---|---|---|
| `sta_nam_kor` | 서산 창리 | — |
| `lat` / `lon` | **36.6163 / 126.3717** | **§5 지점 표와 정확히 일치** |
| `sta_des` | 충남 서산시 부석면 창리 | §0 「창리는 서산시 부석면의 포구」 확인 |
| `bld_dat` | **2017-06-13** | **§3 「창리 관측 개시가 2017-06-13」과 일치** |
| `end_dat` | (빈칸) | 운영 중 |
| `sur_tmp_yn` / `mid_tmp_yn` / `bot_tmp_yn` | **Y / N / N** | — |
| `sur_dep` / `mid_dep` / `bot_dep` | 5 / 10 / (없음) | — |

**PRD가 문서로만 갖고 있던 좌표와 개시일이 기관 API로 교차 확인됐다.**
§16 「출처를 문서에 병기해야 할 것」에 이 API를 근거로 올릴 수 있다.

### 실측값 (2026-08-03 10:30:00)

```
fsch6  서산 창리  2026-08-03 10:30:00  obs_lay=1  29.7℃
fsch6  서산 창리  2026-08-03 10:30:00  obs_lay=2  29.0℃
```

## 3. 응답 항목 전체 (§12 「응답 항목 전체를 기록해야 한다」)

| `repair_gbn` | 상태 (1:정상 2:점검) | |

### `risaCode` — 14개 필드

`gru_nam` · `sta_cde` · `sta_nam_kor` · `bld_dat` · `end_dat` · `lat` · `lon` ·
`sur_tmp_yn` · `mid_tmp_yn` · `bot_tmp_yn` · `sur_dep` · `mid_dep` · `bot_dep` · `sta_des`

### 구현 시 걸릴 것 셋

1. **인코딩이 EUC-KR이다.** JSON도 EUC-KR 선언이라 그냥 읽으면 한글이 깨진다
2. **문서 안에서 철자가 어긋난다.** 항목표 `repaire_gbn`·`resultMng` ↔ 실제 응답 `repair_gbn`·`resultMsg`
3. **`-L` 없이는 0바이트다** (위 1절)

## 4. 발견 — PRD 전제에 걸리는 것 넷

### ① 저층 수온은 오지 않는다 → §6 전제 확인

창리는 `bot_tmp_yn=N`이고 저층 수심 칸도 비어 있다.
**서해 관측소 전체에 저층을 주는 곳이 없다.**
§6이 성층·바람 요인을 M1 범위 밖으로 두며 든 근거("자료가 없다", §15)가
기관 API로 확인됐다. **범위 결정을 바꿀 이유가 없다.**

### ② 그런데 중층은 온다 — 두 응답이 서로 다르다

`risaCode`는 창리를 `mid_tmp_yn=N`이라 하는데,
`risaList` 실측에는 **`obs_lay=2`가 온다**(29.0℃). 수심표도 중층 10m가 적혀 있다.

**`mid_tmp_yn`은 실제 제공 여부와 다른 뜻으로 보인다** *(확인 필요)*.
표층 29.7 − 중층 29.0 = **0.7℃**가 실제로 계산된다.
성층을 요인으로 올릴지는 M1 밖 문제지만, **"자료가 아예 없다"는 서술은 이제 정확하지 않다.**

### ③ 시계열이 없다 → §16 ⑧이 선택이 아니라 결론이 된다

`risaList`는 **최신 스냅숏 한 번**만 준다. 전국 65행이 전부 같은 시각이다.
`sta_cde`·`obs_dat`를 붙여 시험했으나 **두 응답이 바이트까지 동일** — 파라미터가 무시된다.

수산과학원 OpenAPI 8종 전체를 확인했다. **RISA 계열에 기간 조회 서비스가 없다.**
기간 조회가 되는 것(연안정지·정선해양·어장환경·적조·해파리·위성영상)은 **다른 관측망**이라 창리가 없다.

**따라서:**

| | |
|---|---|
| 과거 자료 | 연도별 zip (이미 확보. 변경 없음) |
| 실시간 | **우리가 매시간 쌓는다** (§12 갱신 파이프라인이 그 일을 한다) |
| 결과 | 하루 **24점**. §8이 정의한 `rolling_24h` = 30분 간격 **48회**를 실시간에서 채울 수 없다 |

**§16 ⑧「30분→1시간 변환 여부」는 결정 사항이 아니라 이미 정해진 것이다.**
다만 이것이 **과거 재현에도 1시간을 강제하는지는 별개 결정**이다 —
과거 zip은 30분 간격이 그대로 있으므로, 과거는 48 / 실시간은 24로 갈 수도 있다.
**그 경우 채점이 서비스를 보증하지 못한다**(§14 #19가 창 규칙에서 든 것과 같은 논리).
**⑧의 남은 질문은 "변환하는가"가 아니라 "과거도 1시간으로 내리는가"다.**

### ④ 실시간 제공 지점은 지도의 여섯 곳 중 셋뿐이다

| 지점 | 실시간 | 층 |
|---|---|---|
| 서산 창리 (fsch6) | 있음 | 표층 · 중층 |
| 서산 지곡 (sj086) | 있음 | 표층 |
| 태안 고남 (br001) | 있음 | 표층 |
| 태안 안면도 (btai5) | **없음** | — |
| 태안 내포 (btni5) | **없음** | — |
| 보령 삽시도 (bbsi5) | **없음** | — |

과거 zip에는 여섯 곳이 다 있다. **이 목록은 "지금 실시간으로 제공되는 곳"이라 범위가 다르다.**
지도는 설명하지 않는 지점에 수온을 띄우지 않으므로(§5) **화면은 지금 그대로 두어도 문제없다.**
§5 지점 표에 이 사실을 적을지는 결정이 필요하다.

**참고:** `risaList` 응답에 `obs_dat`가 `2026-04-16`인 관측점이 섞여 있다.
4월 이후 갱신이 멈춘 지점이 있다는 뜻이므로, **갱신 파이프라인은 `obs_dat`가 오늘인지 검사해야 한다.**

## 5. CHANGES.md 반영 후보

PRD 파일은 승인 전까지 고치지 않는다. 아래는 다음 판 후보다.

| 절 | 무엇 | 왜 |
|---|---|---|
| §1 | RISA와 실시간어장정보는 「별개 창구」가 아니다 | id가 `risaList`. 같은 시스템의 API 창구 |
| §12 | 인증키 발급처가 공공데이터포털이 아니라 수산과학원 | 「인증키는 세 종류다」 표 정정 |
| §12 | API 주소·리다이렉트·EUC-KR을 명시 | 파이프라인 구현의 전제 |
| §8 | `rolling_24h` 48회 → 실시간에서는 **24회** | ③ |
| §16 ⑧ | 「변환 여부」 → 「**과거도 1시간으로 내리는가**」로 질문이 바뀜 | ③ |
| §5 | 지점 표에 실시간 제공 여부 열 | ④ |
| §6·§15 | 「저층 자료가 없다」는 맞으나 **중층은 있다** | ② |
| §12 | 갱신 파이프라인에 `obs_dat` 최신성 검사 추가 | ④ 참고 |

### 오늘 별도로 나온 §13 두 건 (API와 무관)

| 절 | 무엇 |
|---|---|
| §13 실패 기준 | `12.6%`·`실효 독립 검정 수 1.3개`가 **3.6 값**이다. 3.7 재계산값은 열유입만 10.8%(1.08개) / 하나라도 18.2%(1.91개) |
| §13 일치율 | `개발용에서 이상군 채택률이 31.6%`가 **3.6 값**이다. 3.7은 44.4% |
| §13 배경장 | 「빼지 않고 남긴다」고 적어놓고 **대표 표는 뺀 값(4.1배)** 을 쓴다. 남긴다면 대표 표가 2.4배여야 하고, 분자 정의도 「하나라도 채택」이어야 한다. **다만 §13이 사전 고정한 배경장 판단 기준은 배경장 단독 채택률을 요구하므로 표에 세 줄이 필요하다** — 열유입 단독 / 배경장 단독 / 하나라도 |
