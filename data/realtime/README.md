## 왜 놓쳤나 — GitHub Actions `schedule` 을 못 믿는다

2026-08-03 16:30 에 워크플로를 켜고 2026-08-04 10:30 에 확인한 결과다.

| | |
|---|---|
| 워크플로 등록 | `state=active` · `.github/workflows/collect.yml` |
| cron | `'5 * * * *'` — 로컬·원격 파일 모두 확인 |
| 기본 브랜치 | `main` (schedule 은 기본 브랜치에서만 돈다 — 조건 충족) |
| **기대 실행 수** | **약 16회** (18시~10시) |
| **실제 실행 수** | **2회** — 08-04 `01:58` · `05:46` |
| **그 2회의 결과** | 둘 다 `success` **인데 커밋 없음** — 아무것도 안 쌓았다 |
| 수동 실행 | 2회 모두 정상 동작 (08-03 16:36 · 16:48) |
| 로컬 실행 | **여섯 번 모두 정상** |

**두 가지가 겹쳤다.** ① 스케줄이 16회 중 2회만 돌았다. ② 그 2회도 건너뛰었다.
②의 사유는 **확인하지 못했다** — 실행 로그 내려받기가 저장소 관리자 권한을 요구한다
(`403 Must have admin rights`).

**그래도 ①을 셀 수 있었던 것은 공개 API 로 실행 목록이 보였기 때문이고,
「무엇이 잘못됐는지」를 밖에서 볼 길을 미리 만들어 둔 덕이다** —
`GITHUB_STEP_SUMMARY` 에 사유를 싣게 한 CHANGES #98·#100 이 그것이다.
**그것이 없었으면 어제 진단 자체가 불가능했다.** 다음에 워크플로를 만들 때도
**성공/실패와 그 사유를 요약에 남기는 것**을 먼저 넣는다.

**어느 쪽이든 매시 수집에는 못 쓴다.** ①만으로도 실격이다.

## 지금 도는 것 — `launchd` (이 맥)

| | |
|---|---|
| 등록 | `~/Library/LaunchAgents/kr.sst-explainer.collect.plist` |
| 부르는 것 | `scripts/collect-local.sh` → `scripts/collect.py` |
| 주기 | `StartCalendarInterval` **매시 :05** · `RunAtLoad` 로 등록 즉시 1회 |
| 로그 | `data/realtime/collect.log` (`결과:` 한 줄이 매번 남는다) |
| 전환 시각 | **2026-08-04 10:33 KST** |

**git 을 건드리지 않는다.** 파일만 쌓고 커밋은 사람이 하는 일에 묻어간다 —
자동 커밋을 넣으면 PRD 를 고치는 중에 끼어들어 반쯤 고쳐진 상태를 커밋할 수 있다.

> **그 뒷면 — 수집분이 이 맥에만 쌓인다.**
> 「영구 보관」을 정한 근거가 **「다시 얻을 수 없다」**였는데, 로컬에만 있으면
> 맥이 잘못됐을 때 그대로 사라진다. **하루 한 번은 커밋·push 한다**
> (`인수인계.md` 「매일 첫 걸음」 0번).

### 이 방식의 한계 — 알고 쓴다

- **맥이 자거나 꺼져 있으면 안 돈다.** 밤새 절전이면 그 구간이 또 빈다
- **이 맥에서만 쌓인다.** 커밋·push 를 안 하면 다른 곳에서 안 보인다
- 둘 다 GitHub Actions 에는 없던 약점이다. **대신 실제로 돈다**

### 확인하는 법

```
launchctl list | grep sst-explainer          # 등록돼 있나
tail -5 data/realtime/collect.log            # 마지막 결과
wc -l data/realtime/fsch6-2026-08.ndjson     # 하루면 48줄씩 는다
```

### 끄고 켜기

```
launchctl unload ~/Library/LaunchAgents/kr.sst-explainer.collect.plist
launchctl load   ~/Library/LaunchAgents/kr.sst-explainer.collect.plist
```

## 워크플로는 남겨 둔다

`.github/workflows/collect.yml` 을 지우지 않았다. **끄지도 않았다.**
돌면 쌓이고, 안 돌아도 launchd 가 같은 파일에 쌓는다.
같은 관측 시각이 두 번 들어올 수 있는데 **중복 제거는 계산할 때 한다** — 원칙 2.

`fetched_at` 이 다르므로 **어느 경로로 언제 받았는지가 줄마다 남는다.**
