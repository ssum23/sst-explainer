## 2. 결정 1 — `withheld`는 수온을 못 믿는 경우만이다

> **`stage: "withheld"` 는 수온 사유일 때만 쓴다.**
> 평년 3년 미만 · ASOS 미산출은 **`stage` 를 정상값으로 두고** 해당 값만 `null`,
> 그룹은 `adopted: null` 로 표현한다.

**근거 둘.**

**① §8의 보류일 규약은 수온 결측에만 맞는다.** §8:783-791이 `current_sst`·`climatology_mean`을
전부 `null`로 두는데, ASOS 미산출인 날은 **수온도 평년 대비도 멀쩡하다.**
`null`로 덮으면 **있는 자료를 감추는 것**이고, §8이 「담아두면 왜 있는데 안 쓰냐는 질문이
생긴다」고 한 논리가 여기서는 **정확히 반대로** 작동한다 — 「왜 있는데 안 보여주냐」가 된다.

**② §8이 이미 갈라 둔 `adopted` 규약과 맞는다.** `false`는 「봤는데 못 미쳤다」,
`null`은 「못 봤다」다. **평년 3년 미만은 「못 봤다」이지 「수온을 못 믿는다」가 아니다.**

`stage`는 일평균의 **절대값**(25/28℃)으로 정해지므로 평년이 없어도, 요인이 없어도 낼 수 있다.

### 실제로 그렇게 나오는지 확인했다

| 사유 | 날 | `stage` | 수온 | 평년 | 편차 | 그룹 |
|---|---|---|---|---|---|---|
| **평년 3년 미만** | 2020-05-15 | `normal` | **16.63** | `null` | `null` | 열유입 `adopted:null` · `quality:partial` (값 17.8571 / 21.0286 은 있다) |
| **ASOS 미산출** | 2021-08-13 | `advisory` | **28.41** | **27.06** | **1.35** | 열유입 `adopted:null` — 일사 `null` / 기온 `ok` 33.0571 |

**ASOS 미산출인 날은 수온·평년·편차가 전부 화면에 남는다.** 결정 1이 지키려던 것이 이것이다.

## 3. 결정 2 — `withheld_reason` enum

| 코드 | 언제 | 개발용 |
|---|---|---|
| `sst_missing` | 결측률이 20%를 넘음 | 20일 |
| `sst_absent` | 그날 관측 행이 아예 없음 | 2일 |
| `station_not_started` | 관측 개시 전 | (2017-05-15~06-12) |

**셋으로 나누는 이유.** §13 보류율 표가 이미 「관측 자체가 없던 날 31」과
「결측률 20% 초과 28」을 갈라 세고, CHANGES #12가 그 31 중 **29가 개시 전**임을
병기하기로 했다. **표가 세 갈래인데 필드가 하나면 표를 근거 파일로 재현할 수 없다.**

> **`station_not_started` 는 근거 파일에서 절대 나타나지 않는다.**
> §3이 2017~2019는 근거 파일을 만들지 않는다고 했고, 2020년 이후는 전부 개시 후다.
> **§13 보류율 집계(2017~2021)에서만 쓴다.**
> 이 주석을 남기지 않으면 다음 사람이 「왜 이 코드는 한 번도 안 나오나」로 막힌다.
> `check_schema()` 가 근거 파일에서 이 코드가 나오면 **실패**시킨다.

## 8. 결정 7 — 실시간 형태

③의 범위는 **필드 규칙**까지다. 견본 D 선정은 2주차(§9)에 둔다.

| 필드 | 과거 재현 | 실시간 |
|---|---|---|
| `observed_at` | 날짜 | **날짜+시각** |
| `sst_basis` | `daily_mean` | `rolling_24h` |
| `obs_count` | 그날 (만점 24) | **최근 24시간** (만점 24) |
| **`daily_max_sst`** | 담는다 (30분 기준) | **`null`** |
| `days_over_advisory` | 당일 포함 | **완료된 날까지만** (§8이 이미 규정) |

> **`sst_basis == "rolling_24h"` ⟹ `daily_max_sst == null`.** `check_schema()` 가 검사한다.

**「최근 24시간 최고값」은 일 최고수온이 아니라 다른 물건이다.** 같은 필드에 다른 정의를
담으면 §2가 「같은 28℃가 두 곳에서 쓰이고 섞으면 안 된다」고 경계한 상황이 그대로 재발한다.
게다가 ⑧에서 `daily_max_sst`만 30분(만점 48)으로 남겼으므로, 실시간에서 만들면 24점의 max라
**과거와 성질이 다르고** §14 #19의 「과거와 실시간이 다른 물건이면 채점이 서비스를
보증하지 못한다」가 그대로 걸린다.

「스키마가 두 얼굴」이라는 우려는 **`sst_basis` 필드가 이미 그 구분을 담고 있어** 문제가 아니다.

## 10. 결정 1이 드러낸 화면 문제 둘

### ① 모든 그룹이 `adopted:null` 인 날, 화면이 **거짓을 말한다**

`assets/station.js:374`:

```js
var adopted = groups.filter(function (g) { return g.adopted; });
...
if (!adopted.length && groups.length) {
  body.appendChild(el('p', …, '평년을 크게 벗어난 요인이 없습니다.'));
}
```

**`null` 은 falsy 다.** 모든 그룹이 `adopted:null` 인 날 `adopted.length === 0` 이 되어
**「평년을 크게 벗어난 요인이 없습니다.」를 출력한다.** 보지도 않고 평범했다고 말하는 것이며,
**§8:770이 「`null` 을 `false` 로 뭉치면 확인하지 않은 것을 확인한 것처럼 주장하게 된다」고
금지한 바로 그 동작이다.**

**§11에 그런 날의 문구가 없다.** §11 요인 영역이 가진 것은 둘뿐이다 —
「채택 없음」과 「그룹 미채택」. **셋째 경우가 규정되지 않았다.**

지금은 잠복이다(견본 셋 다 해당 없음). **평년 3년 미만 28일이 렌더되면 드러난다.**

**필요한 것:** §0의 「원인이 없으면 없다고 말한다」를
**「판정할 자료가 없으면 없다고 말한다」**로 확장하는 한 줄.

| 상황 | 지금 | 있어야 할 것 |
|---|---|---|
| 채택 0 · 전부 `false` | 「평년을 크게 벗어난 요인이 없습니다.」 | 그대로 |
| 채택 0 · 전부 `null` | **같은 문구 (거짓)** | 「**요인을 판정할 자료가 부족합니다.**」 |
| 채택 0 · 섞임 | **같은 문구 (일부 거짓)** | 판정한 것만 두고 말하거나, 문구를 빼고 카드에 맡긴다 |

### ② 그룹이 `null` 이면 **아는 요인 값까지 감춰진다**

2021-08-13(ASOS 미산출)은 일사가 `null` 인데 **기온은 `ok` 이고 백분위까지 있다.**
그런데 `station.js:316` 이 `isUnknown(g)` 에서 **카드를 통째로 조기 반환**해
「값을 아직 확인하지 못했습니다」만 남기고 **기온 33.0571 을 그리지 않는다.**

§8:769의 규약(`null` → 막대 없음)을 그대로 따른 것이라 **코드가 틀린 것은 아니다.**
다만 §14 #26이 「미채택 그룹도 값과 막대를 보여준다 — 왜 못 미치는지 화면에서 알 수 없었다」고
정한 취지와 **같은 종류의 손실**이다. 그룹 판정은 못 해도 **본 요인은 보여줄 수 있다.**

**결정이 필요하다.** `adopted` 는 그룹 단위인데 `quality` 는 요인 단위라, 화면이
어느 쪽을 따를지가 §8·§11에 없다.

## 11. #69 · #70 — 고쳤다 (같은 날)

원칙 두 줄을 받아 `assets/station.js` 를 고쳤다. **§11 문구가 확정되기 전이라 화면은 잠정이고,
PRD 와 어긋나는 것은 CHANGES #69·#70·#71·#72 에 쌓았다.**

### #69 — 요약 문구는 「봤다」가 전제다

> `adopted: null` 이 하나라도 있으면 **「없습니다」라고 말하지 않는다.**

| 상황 | 요약 |
|---|---|
| 채택 있음 | 없음 |
| 채택 0 · **전부 `false`** | 「평년을 크게 벗어난 요인이 없습니다.」 |
| 채택 0 · **전부 `null`** | 「요인을 판정할 자료가 부족합니다.」 |
| 채택 0 · **섞임** | **없음 — 그룹 카드가 각자 말한다** |

**섞였을 때 요약을 억지로 만들지 않는다.** 섞인 상태를 한 문장으로 요약하면
반드시 과장이거나 축소다.

### #70 — 판정과 표시는 별개다

> **`adopted` 는 그룹 단위 · `quality` 는 요인 단위. 두 축이 독립이다.**
> `adopted: null` 은 **판정을 못 한다**는 뜻이지 있는 값을 감추라는 뜻이 아니다.

| `quality` | 화면 |
|---|---|
| `ok` | 값과 **막대**를 그린다 |
| `partial` | **값만** 적는다 (백분위가 없어 막대를 그릴 위치가 없다) |
| `null` | 「자료 없음」 |

카드 하단도 갈린다 — 본 요인이 하나라도 있으면 **「일부 요인의 자료가 없어 판정하지 못했습니다」**,
하나도 없으면 「값을 아직 확인하지 못했습니다」. **값을 화면에 그려 놓고
「값을 아직 확인하지 못했습니다」라고 하면 화면이 자기 자신과 어긋난다.**

### 네 경우를 실제로 돌렸다 (`node`)

| 경우 | 요약 | 카드 |
|---|---|---|
| 견본 A (열유입 채택 + 배경장 `null`) | (없음) | heat 막대 2/2 「채택 사유」 · bg 막대 0/1 「값을 아직 확인하지 못했습니다」 |
| 견본 B (둘 다 미채택, 전부 봤다) | **「평년을 크게 벗어난 요인이 없습니다.」** | 둘 다 막대 그림 「판정 기준에 못 미칩니다」 |
| 평년 3년 미만 | **「요인을 판정할 자료가 부족합니다.」** | heat 막대 0/2 (값은 적힌다) |
| **ASOS 미산출 (섞임)** | 「요인을 판정할 자료가 부족합니다.」 | **heat 막대 1/2** — 기온만 그린다 · 「일부 요인의 자료가 없어 판정하지 못했습니다」 |

**네 번째가 #70이 지키려던 것이다.** 기온 33.0571 이 화면에 남는다.

### `check_schema()` 에 회귀 가드를 넣었다

`factors_summary(doc)` 가 `station.js renderFactors` 와 **같은 규칙을 파이썬으로** 갖는다.
`check_schema()` 는 **`adopted:null` 이 있는데 요약이 「없습니다」면 실패**시킨다.

**현재 구현으로는 깨질 수 없다 — 회귀 방지 가드다.**
`station.js:374` 의 옛 버그(`filter(g => g.adopted)` 로 `null` 을 falsy 로 뭉갬)를
파이썬에 되살려 시험했고, **정확히 잡는다.**

```
정상 구현: 통과
옛 버그 되살림: ['adopted:null 이 있는데 요약이 「평년을 크게 벗어난 요인이 없습니다.」다']
```

### `hasBar` 도 함께 고쳤다

`ⓘ` 안내를 띄울지 정하는 `hasBar` 가 `!isUnknown(g)` 로 **그룹 단위 판단**이었다.
#70 으로 `null` 그룹도 막대를 가질 수 있으므로 **요인 단위**로 바꿨다.
